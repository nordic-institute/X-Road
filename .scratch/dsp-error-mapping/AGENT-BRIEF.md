# Agent Brief — DSP Error Semantics Preservation

> *This was generated by AI during triage.*

**Read first:** [`PRD.md`](PRD.md) in this directory.

## Mission

Post-edc17, DSP catalog/contract failures collapse into generic `NETWORK_ERROR` or `INTERNAL_ERROR`, breaking system-tests that depend on the historical X-Road error contract (`unknown_member`, `io_error`, `service_failed`, ...). Map EDC failure shapes to concrete `ErrorCode`s on the control-plane side, and stop the consumer-side processor from masking homogeneous remote errors with a blanket `NETWORK_ERROR`.

## Approach

1. **Test-first.** Author `DspFailureClassifierTest` and extend `ConsumerSideDspProcessorTest` before changing any production code. Both tests must run red before any implementation.
2. **Classifier as a pure function.** `DspFailureClassifier.classify(Throwable cause) → XrdRuntimeException`. No state, no I/O. Trivially testable.
3. **Confirm gRPC end-to-end.** Verify with a focused test on `RpcResponseHandler` / `AbstractRpcClient` that an `XrdRuntimeException` with a non-default code arrives back at the client with that code preserved. (This is likely already covered — check before assuming.)
4. **Be conservative on the consumer.** When in doubt, keep current `NETWORK_ERROR` behavior. Only collapse to a specific code when ALL candidates report the same `XrdRuntimeException` code.
